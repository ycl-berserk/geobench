# T041 的失败留档

项目规矩：**被拒的 Agent 产出必须留档，不许删除**（`docs/ai-workflow.md` §6）。
这里记的是 AI 作图通道**实测中被拒的产出**——每一份都是真模型的原话，
因为它们是这份 skill 的**教材**：每一条都对应一个具体改动。

服务：DeepSeek（`DEEPSEEK_API_KEY`），温度 0。

---

## 一、漏了「点」字（6/6 全灭的原因）

```点 A(2,3) B(5,0) C(2,3)
lAB = 线段(A, B)
lBC = 线段(B, C)
lCA = 线段(C, A)
O = 外心(A, B, C)
H = 垂心(A, B, C)
G = 重心(A, B, C)
```

解析器说：「第 1 行第 1 列：不认识的命令 'A'」。

**为什么它没用**：那句话没说怎么改。模型重试了一次，写的是**一模一样的东西**
（重试机制只在「错误信息可操作」时才有意义）。

**改了什么**：
1. 规则里点名「点」字不能省，并且给了例子；
2. **错误信息改成能照着改**：「自由点要写成「点 A(x, y)」——「点」字不能省」。

## 二、断言写错了（九点圆那题）

```
点 A(2,3) B(0,0) C(5,0)
AB = 线段(A, B)
BC = 线段(B, C)
CA = 线段(C, A)
bc = 直线(B, C)
ah = 垂直(A, bc)
H = 交点(ah, bc)
M = 中点(A, B)
N = 中点(A, C)
w = 外接圆(A, B, C)
断言 共圆(M, N, H, A)
```

内核查出「断言 `共圆(M, N, H, A)` 在这张图上不成立」——**这句是对的**：
M、N 是中点，不在外接圆上，模型把「在圆上」和「共圆」搞混了。

**为什么它没用**：题面「证明 M、N、H 在外接圆上」没有说清是**四个点共圆**，
模型自己猜了一个形式。

**改了什么**：用例改成把结论**说死**（「证明 D、M、N、H 共圆」），
并教了「点在」这个写法（`断言 点在(M, w)`）。

## 三、偷偷换了一张图（圆内点作切线那题）

```
点 O(0,0) A(2,0)
c = 圆(O, A)
P = 圆上的点(c, 1/4)
t = 切线(P, c)
```

题目要的是「**圆内**一点 P」，模型给了「**圆上**一点 P」——图是好的，
但**不是题目的图**，而且**一句话没说**。

**为什么它没用**：题面要的东西**做不到**（圆内一点没有切线），
而提示词只说「只输出作图代码」，模型没有地方说「做不到」。

**改了什么**：
1. 规则里加了一条：「做不到的请求，就写一行 `# 做不到：为什么`」；
2. 评测集加了一个**必须抓住**这种偷偷替换的检查（`must_not_relate`）。

同一次实测，模型改成了这样：

```
# 做不到：切线要求点在圆上，而题面要求 P 在圆内；从圆内一点作圆的切线不存在（实切线），且本作图语言只支持"圆上一点处的切线"，无法从圆内点作切线。
```

**这是最好的答案** —— 它没有硬画一张假图。

## 四、图外点的切线（软件本身缺的那块）

```
点 O(0,0) A(2,0) P(4,0)
c = 圆(O, A)
t = 切线(P, c)
```

这是**我们自己的例子**（第一版的规范里就是这么写的），结果**内核拒绝了**：
`切线` 是**圆上那一点处的切线**，P 必须在圆上；从圆外一点作切线**本软件做不了**。

**为什么它没用**：我们自己写的例子就是错的。
一个例子错了，比十条规则加起来更糟 —— 规则会被照着抄，例子会被抄成错的。

**改了什么**：例子改对，规范里写死「做不到的事」，
并把这条记成 T042 的候选（GeoGebra 的 `切线(点, 圆)` 对圆外一点给**两条**切线，
而本 DSL 一条命令只出一个对象 —— 选哪一条是语义问题）。

## 五、评测集自己的错（不算 AI 的错，记在这里）

用例里写了 `断言 相等(AB, AC)`，解析器说「命令 '相等' 不能接受这些参数」。
查下去发现是**我们的问题**：*画出来的*线段不记得自己的两个端点，
所以打不开；而写成两个字母的线段记得。**修好了软件**，用例不用改。

还有一处：直角三角形那题，我原本把「直角在 A」写成了检查 B 处的角，
**用例自己错了**。评测集也会错，所以它的期望也归 CI 管。

## 六、CI 说「这个门禁根本收不上来」

第一次推送后，CI 红了：

```
ModuleNotFoundError: No module named 'evals'
```

评测集住在仓库根目录，而 CI 跑的是裸 `pytest -q` —— 不是 `python -m pytest`，
所以**当前目录不在 sys.path 上**，门禁连导入都做不到。

**为什么它没用**：本地跑的一直是 `python -m pytest`（它会把当前目录加进 sys.path），
所以本地全绿、CI 全红。**本地怎么跑，CI 就得怎么跑** —— 门禁要按 CI 的方式跑一遍才算数。

**改了什么**：

1. `pyproject.toml` 的 `pythonpath` 加上 `"."`（跟 `"src"` 挤着）；
2. CI 的门禁清单里加上 `eval` 这一条 —— 以前它根本不在清单里，
   **没进清单的门禁不算门禁**。
