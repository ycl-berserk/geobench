# T059 —— 自由数值 + 滑块

**状态**：已实现
**负责人**：Agent
**规格**：`docs/spec.md` §3（数）、D18
**依赖**：T015（双路径）、T046（约束求解）
**涉及层**：模型 · DSL · 算子 · 求值 · 应用

## 目标

让"数"成为和点、线、圆一样的对象：`数 a = 2.5`，它可以当半径、角度、比例、参数；
画布上有一条滑块，拖动它整张图跟着变。它是**轨迹**（T031）和动画的地基。

## 做法

### ① 数是一个精确常量

- `number.free` 节点：`kind=number`、`role=free`、`args=[精确值]`；`2.5` 存成 `5/2`，
  因为内核是精确的，滑块上的小数只是输入方式；
- DSL 新增语句 `数 a = 2.5`（英文 `Number a = 2.5`），`to_dsl` 写在自由点之前；
- 求值：数值路径把自由数写进载荷（`value`）；精确路径跳过它，但任何读它的构造
  通过 `OpContext.scalar` 拿到**精确值**；
- `scalar` 只接受自由数；测量值（`长度(AB)`）依赖图，不能当参数 —— 明确拒绝，
  不静默近似。

### ② 数字参与构造

`OpContext.scalar(arg)`：字面量或自由数的精确值。已接入：

- `圆(P, a)` 半径、`旋转(B, a, A)` 角度、`位似(…, a, …)` 比例；
- `点(对象, a)`（线上的点）的参数。

**顺带修正一个语义错误**：`圆(P, r)` 的第二个参数一直是"半径的平方"
（`圆(A,25)` 得到半径 5），而 GeoGebra 和 `docs/dsl-spec.md` 都写的是半径。
参数化让这个错误变得刺眼（`a=3` 会画出半径 √3），所以改成真正的半径，
同步对拍 oracle、测试与命令表摘要。

### ③ 滑块

- 构造栏顶部出现"参数"区：`a [滑块] 2.5 [数字框]`；
- 拖动滑块：只走**数值直算**（同一份算子喂数字），图即时跟手；
- 松手 / 键盘停止 300ms / 数字框回车：调用 `evaluate()` 重建精确表达式，
  因为常量变了，构造本身变了；
- **拖动中不让过期的精确结果落地**：`set_number` 把 `exact_version` +1 并标 pending，
  后台 worker 完成时版本不符就丢弃；
- 一次拖动**一步撤销**（按下时记录快照，途中不记录）。

## 非目标

- 数的四则运算表达式（`a = b + 1`）与派生数；
- 测量值当参数（需要一条"参数依赖图"的规则）；
- 滑块范围自定义（现在是 −10…10，数字框到 ±1e6）；
- 轨迹（T031）—— 下一项。
