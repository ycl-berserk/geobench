### F1 — 2026-11-08 · `circle.through` 丢掉了外心的条件

- **症状**：三点共线时，圆的圆心算出来是**复数** ✓，然后程序崩 ✓。
- **根因**：`circle.through` 借用了 `op_circumcenter` 的**坐标** ✓，把外心顺带发布的 `must_be_nonzero`（三点不共线）**丢了** ✓ ✗。于是数值层不知道该把这个圆标成 undefined ✓ → 复数一路传到绘制层 ✓。
- **修法**：条件一并传下去 ✓（和弧 `arc.three_points` 一样 ✓ —— 那个当时修对了 ✓，这个漏了 ✓）。
- **本该拦住它的门禁**：**没有** ✗ —— 对拍夹具用的是**具体坐标** ✓（共线时精确层直接报错 ✓ ✓），所以对拍永远碰不到"符号非共线、摆放共线"这种情况 ✓ ✗。
- **动作**：**借别人的计算，就要把它的前提一起借走** ✓。这条我在做弧的时候写过一次 ✓，同一天又在圆上犯了一次 ✓ —— 说明**光记住不够，要有门禁** ✓（现在有了 ✓，就是随机会话 ✓）。

### F2 — 2026-11-08 · 精确路径的兜底把复数变成 `TypeError`，从 paint 里逃出去

- **症状**：`TypeError: Cannot convert complex to float` ✓，然后 `Error calling Python override of QWidget::paintEvent()` ✓，然后程序结束 ✓。
- **根因**：兜底路径 ✓ 直接 `float(sp.N(...))` ✓ —— 复数直接抛 ✓；而绘制事件里的异常 ✓ PySide6 会**让进程终止** ✓。
- **修法**：兜底改成 `_real()` ✓ —— 不是有限实数就抛 **`StateError`** ✓（一个调用方接得住的错误 ✓）；绘制层再把它**跳过** ✓。
- **本该拦住它的门禁**：没有 ✗。
- **动作**：**"没有值"和"出错了"是两件事，但都必须是可以接住的东西** ✓。裸的 `TypeError` 从事件循环里逃出来，代价是整个进程 ✓。

### F3 — 2026-11-08 · 拖动的坐标是浮点数

- **症状**：拖动之后，**所有判定器**失效 ✓：`expression contains a floating point part` ✓。
- **根因**：`move_point` 写的是 `repr(x)` ✓ —— 拖动落在半个像素上，就是 `1.5` ✓。而摆放会参与**符号代入** ✓（判定器读它 ✓），内核的规矩是**不许出现浮点** ✓ → 当场拒绝 ✓。
- **修法**：摆放一律存**有理数** ✓（`29/20` ✓），显示时才换成小数 ✓。
- **本该拦住它的门禁**：**没有** ✗ —— 拖动测试只断言"点动了" ✓ ✓，没断言"还能判定" ✓ ✗。
- **动作**：**"能显示"不等于"能用"** ✓。摆放这种东西，既要给人看 ✓，又要给内核算 ✓ —— 两边都得过 ✓。

### F4 — 2026-11-08 · 撤销不还原标号计数器

- **症状**：撤销之后再放一个点 ✓ → `node id 'B' already exists` ✓。
- **根因**：撤销还原了**图** ✓，没还原**控制器里那个计数器** ✓ ✗。
- **修法**：计数器进快照 ✓ ✓；并且 `_new_label` **跳过已经用掉的名字** ✓ —— 打开文件也会带来名字 ✓，光靠计数器不够 ✓。
- **本该拦住它的门禁**：没有 ✗ —— 是随机会话撞出来的 ✓。
- **动作**：**撤销要还原"状态"，不只是"数据"** ✓。计数器、当前工具、选项，都是状态 ✓。

### F5 — 2026-11-08 · 关系编号用数量推，删一个就重名

- **症状**：`relation id 'r2' already exists` ✓。
- **根因**：编号 = `len(relations) + 1` ✓ —— 删掉一个 ✓ 数量变小 ✓ 下一个就撞上已有的 ✓ ✗。
- **修法**：取**下一个没人用的编号** ✓。
- **动作**：**用"数量"当"编号"是会撞的** ✓ —— 编号只有一个可靠来源：**现在有哪些** ✓。

### F6 — 2026-11-08 · 打开文件必然失败（如果图里已经有点）

- **症状**：`node 'A' is used by l1; remove the dependents first` ✓ —— 打开文件失败 ✓。
- **根因**：`load_text` 是**逐点删除**旧图 ✓，而模型拒绝删"还有依赖"的点 ✓（对**编辑**来说这是对的规矩 ✓）✗。
- **修法**：整张图**直接清空** ✓ —— 换整张图和编辑一个对象是两件事 ✓，规矩也该不一样 ✓。
- **动作**：**同一条规矩，对不同操作的正确性不一样** ✓。模型护着"编辑"✓，控制器负责"换整张"✓。

### F7 — 2026-11-08 · 删点删不掉（断言还引用着它）

- **症状**：`node 'M' is referenced by relation 'r2'` ✓ —— 用户删不掉点 ✓。
- **根因**：模型拒绝删被断言引用的点 ✓（对的 ✓），而控制器没有**级联删掉那些断言** ✓ ✗。
- **修法**：删点 → 连带删掉**关于它**的断言 ✓。
- **动作**：**模型说"不行"，是提醒调用方"你得先做点什么"** ✓ —— 不是让用户自己去想办法 ✓。

### F8 — 2026-11-08 · 摆放改成有理数之后，点"消失"了

- **症状**：拖动之后所有点从命中测试里消失 ✓。
- **根因**：`point_positions` 用 `float(placement)` ✓ —— 而 `"29/20"` 不是浮点字符串 ✓ → `ValueError` ✓ → 那个点被**静默跳过** ✓ ✗。
- **修法**：用 `Fraction` 解析 ✓。
- **动作**：**改一处格式，要顺着它把所有读者找一遍** ✓。类型换了，读它的地方全都要跟着换 ✓ —— 而且**静默跳过**的那种最难发现 ✓。

## 这一条真正的教训

**"退化"这条规矩，我在三层只守住了一层半。**

精确层守住了 ✓（符号上不共线就不算退化 ✓ —— 这是对的 ✓）；数值层**有时**守 ✓；绘制层完全没守 ✓ ✗。

而**用户碰到的永远是绘制层** ✓ ✓。

所以现在有一条正式门禁 ✓：**随机会话 · 每步之后都画一遍** ✓ —— 它把这三层一起按住了 ✓ ✓。
