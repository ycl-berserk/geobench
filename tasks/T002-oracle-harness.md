# T002 — Oracle harness and fixture format

**Status**: proposed
**Owner**: agent
**Spec**: `docs/spec.md` §5.3 (oracle requirement), §13 (acceptance criteria)
**Depends on**: T001
**Layers touched**: infra

## Goal

Every operator can be proven correct against an *independent* implementation before it enters the registry. This is the single most important gate in the project: geometry code that looks right is routinely wrong at the edges.

## Deliverables

- `tests/oracle/harness.py` — given an operator id and a fixture set, run the kernel implementation and the oracle implementation, compare exact results, and emit a structured diff (symbolic difference, not just "not equal").
- `tests/oracle/fixtures/<op>.json` — fixture format: a list of argument tuples, each tagged `{"kind": "normal" | "degenerate", "expect": "value" | "error"}`. ≥ 20 configurations per operator, ≥ 3 tagged degenerate.
- `tests/oracle/oracles.py` — independent implementations. SymPy's own geometry/symbolic routines where they exist, a closed-form expression otherwise, and the GeoGebra JS API as a third opinion for the operators it supports.
- `pytest tests/oracle -q` — a **coverage gate**: fails if any registered Tier-A operator lacks a fixture file or has < 20 configurations.
- `docs/oracles.md` — per operator: what the oracle is, why it is independent, known limits.

## Acceptance criteria

```bash
pytest tests/oracle -q
ruff check . && mypy src
```

Additionally, by hand:
- A deliberately broken operator (mutated in a scratch copy) makes the harness fail with a diff that names the differing coordinate.
- The coverage report lists every registered operator; the report is committed as `tests/oracle/coverage.md` and regenerated by `pytest tests/oracle --coverage-report`.
- Degenerate fixtures assert an *error*, not merely a different value.

## Non-goals

- Implementing the operators themselves (T004).
- Any test of judge semantics (T005 owns the counterexample requirement).
