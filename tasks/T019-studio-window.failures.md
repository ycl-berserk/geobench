### F1 — 2026-11-07 · 面板标题吃掉了半块画布

- **症状**：窗口一打开，中间的画布被挤到面板下半部分，标题"画板"占了上半部分。
- **根因**：`QVBoxLayout` 里标题 `QLabel` 的竖向 size policy 是 `Preferred`，布局把多余空间分给了它。画布在后面，只拿到剩下的。
- **修法**：标题的竖向 size policy 设为 `Fixed`，并且给真正的内容widget 一个 stretch factor（`addWidget(widget, 1)`）。
- **本该拦住它的门禁**：无（是**看截图**发现的）。
- **动作**：**布局的问题只能看截图。** 已经定下的规矩：窗口必须有脚本截图（`scripts/app_preview.py`），改完界面就重截一次。

### F2 — 2026-11-07 · 满屏方框：Qt 一个字体族都没找到

- **症状**：截图里所有中文都是 □。
- **根因**：**不是**代码的问题 —— Qt 的 `offscreen` 平台插件在这台机器上**看不到任何系统字体**（`QFontDatabase.families()` 返回 0 个）。换回 `windows` 平台插件，342 个字体族，`Microsoft YaHei UI` 就在里面。
- **修法**：主题模块显式挑中文字体（按优先级列表取第一个系统有的），并且**默认用真实平台**而不是 offscreen。
- **本该拦住它的门禁**：无。
- **动作**：两件事分开记：**方框是环境问题，字体没挑是代码问题。** 后者要修（显式挑字体），前者要记（无头测试用 offscreen，截图用真实平台）。

### F3 — 2026-11-07 · `point.foot` 不接受线段

- **症状**：`point.foot(A, BC)` 报"argument 1 should be a line, got 'BC'"，而 BC 明明是一条**线段**。
- **根因**：算子的参数类型写的是 `line`，而 store 的参数检查要求节点种类**严格等于** `line`。但内核的 `ctx.as_line` 接受线段（线段携带一条直线）。
- **修法**：参数类型 `line` 接受 `line` **或** `segment`。
- **本该拦住它的门禁**：`unit`（但这条路径之前只有 DSL 用，而 DSL 不走 store）。
- **动作**：**同一份契约有两条路**（DSL 直接建图 vs store 施加操作），检查的严格程度就会不一致。**契约要在最靠近数据的地方检查一次**，别指望每个入口都检查。

### F4 — 2026-11-07 · 截图里判定表是空的

- **症状**：表格有 3 行（行号都在），但单元格是空的。
- **根因**：`refresh()` 填了单元格，但截图在 Qt 重绘之前就抓了。
- **修法**：截图脚本里多跑几轮 `processEvents()`。
- **本该拦住它的门禁**：无。
- **动作**：截图脚本本身也是代码，**它需要"确定性地拿到最终画面"** —— 抓之前必须让事件循环把重绘做完。
