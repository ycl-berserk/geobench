### F1 — 2026-11-07 · 查不到 GeoGebra 的中文命令名

- **症状**：想核准命令的中文名，GeoGebra 的 wiki（`wiki.geogebra.org/zh/命令`）连不上，GitHub 的整树 API 超时，手册本身只有英/德/西/法/日等语言，**没有中文版**。
- **根因**：GeoGebra 的中文界面文案在它自己的翻译资源里，那个仓库很大，按目录逐层翻不现实。
- **修法**：改从**GeoGebra 自己的中文材料**里取（繁中教学页里出现的工具名：中垂線、角平分線、交點、圓心一點、內心、外心、中點、位似、反射變換），加上中文数学的通用术语，得到命令表里的中文名。**并且**决定：**英文名始终接受**。
- **本该拦住它的门禁**：无。
- **动作**：**查不到权威数据时，不要假装权威。** 这里的做法是：(1) 用能核到的来源；(2) 把"英文名也接受"做成硬需求，让中文名错了也只是不方便，不是不能用；(3) 命令名集中在**一张表**里 —— 以后要改，改一处。

### F2 — 2026-11-07 · "命令名唯一"这条测试本身是错的

- **症状**：测试报 `垂直` 既属于 `line.perpendicular_through` 又属于 `perpendicular`。
- **根因**：**重载是 GeoGebra 的正常设计**（`交点` 三种、`圆` 两种），测试却假设名字唯一。
- **修法**：把测试改成"**重载必须能靠参数分开**" —— 同名命令的签名（种类 + 参数个数 + 参数种类）必须互不相同。这条测试比"名字唯一"有用得多：它保证 DSL 永远猜得出写的是哪一个。
- **本该拦住它的门禁**：无。
- **动作**：**写下来的断言要问一句"它真的是我想要的吗"。** "名字唯一"听着合理，但它禁止了 GeoGebra 本身就在做的事。

### F3 — 2026-11-07 · 表里漏了三个已有的判定器

- **症状**：`test_every_judge_we_have_is_in_the_table` 报 `midpoint_of` `point_perpendicular` `angle_bisector` 不在表里。
- **根因**：表是**照着手册**列的，而这三个判定器是**我们自己加的**（GeoGebra 不能判定，所以这三个关系没有 GeoGebra 对应物）。
- **修法**：补进表里，并在注释里写明"这三个没有 GeoGebra 对应物，因为 GeoGebra 根本不判定"。
- **本该拦住它的门禁**：无（表刚建，还没有这类门禁）。
- **动作**：**表里要分清"GeoGebra 的命令"和"我们自己的命令"。** 混在一起会让"对齐 GeoGebra"这个目标本身变得含糊。
