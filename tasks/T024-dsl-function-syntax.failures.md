### F1 — 2026-11-07 · 汉字被一个一个切开，`中点` 变成 `中` + `点`

- **症状**：`中点(A,B)` 解析成"命令名是 `中`"，因为旧的词法器把不在关键字表里的汉字**一个一个**当标识符。
- **根因**：旧词法器的关键字表是**硬编码**的，里面有 `中点` `交点` `共线` …… 每加一个命令就要改词法器。
- **修法**：汉字**整串**切成一个词；关键字表只剩 `点` `断言` 两个**语句头**，其余都是名字，由命令表解析。
- **本该拦住它的门禁**：无（词法器的行为变了，但旧测试全用旧语法，照样过）。
- **动作**：**词法器不该知道命令名。** 名字是**语义**层的事，放在命令表里；词法器只管切词。这条分界线让"加一个命令"变成"加一行表"。

### F2 — 2026-11-07 · 选择器 `另一交点` 被当成节点 id，模型报错

- **症状**：`node 'P' references unknown node id '另一交点'`。
- **根因**：解析器把选择器原样写进了 `node.args`，而构造图的参数要么是节点 id，要么是**字面量**（数字）。`另一交点` 两样都不是。
- **修法**：命令表里加一张 `中文选择器 → 规范值` 的表（`另一交点` → `other`）；构造图里存规范值，DSL 文本里写中文词。算子本来就只认 `0` / `1` / `other`。
- **本该拦住它的门禁**：无。
- **动作**：**参数有两种身份**：引用（节点 id）与字面量（数字、选择器）。模型认得数字，不认选择器 —— 说明选择器的规范值应该与算子的约定一致，而不是 DSL 自己发明的。

### F3 — 2026-11-07 · 关系的重载分不开：`垂直` 有三种意思，参数个数也一样

- **症状**：`断言 垂直(A,l)` 该选"点垂直"，却可能选成"两线垂直" —— 两者都是两个参数。
- **根因**：判定器的规格里**没有参数类型**（只有参数名 `p1` `p2`），所以只能按个数消解。
- **修法**：命令表给每条关系补 `arg_kinds`（`"line"` / `"point"` / `"any"`），解析器按它消解。
- **本该拦住它的门禁**：无。
- **动作**：**重载能安全存在的前提是"参数能区分开"**。所以命令表里必须写清楚每条命令的参数契约 —— 名字不够，名字只是入口。

### F4 — 2026-11-07 · 小数坐标被切错：`2.5` 变成 `2` 和 `5`

- **症状**：`点 A(2.5,1)` 报"两个坐标之间应该有逗号"。
- **根因**：旧词法器的数字分支只认整数与分数 `1/2`，**不认小数**；而 `.` 又不属于任何可识别字符，于是被**悄悄丢掉**。
- **修法**：数字分支补上小数；不认识的字符不再静默丢弃，而是记成一个符号 token，让解析器能说清"这里不该有这个"。
- **本该拦住它的门禁**：无。
- **动作**：**静默丢弃是解析器最坏的失败方式** —— 它把错误挪到了别处。现在不认识的东西会留下痕迹。
