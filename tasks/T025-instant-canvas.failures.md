# T025 失败记录 —— 画板掉进了精确路径

按 `docs/ai-workflow.md` §6 留档。

### F1 — 2026-11-09 · 有理数放置值被当成"没有值"

- **症状**：把一个点拖到非整数坐标（比如 1.01）✓，**整张图的对象全部变成 undefined** ✓，画面上什么都没有 ✓。
- **根因**：放置值是**精确的有理数** ✓（`"101/100"` ✓，因为放置值要喂给判定器的符号代入 ✓），而数值路径用 `float(node.placement[0])` 读它 ✓ —— `float("101/100")` 抛 ValueError ✓ → 被 `except` 吞掉 ✓ → 这个点"没有值" ✓。
- **修法**：`numeric.placement_float` ✓ —— 先试 `float` ✓，再试 `Fraction` ✓。
- **本该拦住它的门禁**：**没有** ✗ —— 性能基准里的放置值是 `str(index % 7)` ✓，**全是整数** ✓，正好绕开了 ✓。
- **动作**：**基准数据要像真的。** 拖动过的点就是有理数 ✓ —— 基准就该用有理数 ✓。

### F2 — 2026-11-09 · 图元层回退到精确路径

- **症状**：**几十个对象的图，重画一次要几分钟** ✓；36 个对象就再也画不出来 ✓。
- **根因**：图元层在数值缓存里找不到值时 ✓，调用 `numeric_coords` ✓ —— 那个函数有一条**符号回退路径** ✓（给"从没数值求值过的图"用的 ✓）→ 走 `free_symbols` ✓ → `FIELD.coerce` ✓ → **SymPy 的 `parse_expr`** ✗✗。
- **而且**：`_label_offset` 给**每个标签**都重算一次质心 ✓，质心又要问**每个点**的坐标 ✓ → **O(n²) 次字符串解析** ✗✗。
- **修法**：图元层**只读数值缓存** ✓，没有值就不画 ✓（决策 D18 ✓：屏幕只看数值路径 ✓）；质心**每张图算一次** ✓。
- **本该拦住它的门禁**：**没有** ✗ —— 性能基准量的是 `evaluate_exact` + `evaluate_numeric` ✓，**没有量出图** ✗✗ —— 而慢的正是出图 ✓。
- **动作**：**门禁要量用户看见的那件事。** 我们量了内核 ✓，没量画板 ✓ —— 而用户看的就是画板 ✓。

### F3 — 2026-11-09 · 精确路径反复解析同样的字符串

- **症状**：每加一个构造都要多花一点时间 ✓，而且是**线性增长** ✓（2.4 ms → 3.1 ms ✓）。
- **根因**：`FIELD.coerce("x_A")` ✓、`FIELD.coerce("101/100")` ✓ 每次求值都重新 `sympify` 一次 ✓ —— 而这些字符串**每次都一样** ✓。
- **修法**：`SympyField._parse` ✓ 记住解析过的字符串 ✓（SymPy 表达式不可变 ✓，共享安全 ✓）。
- **动作**：**同一个输入反复出现，就该只算一次。** 这条对精确路径尤其重要 —— 它的输入是字符串 ✗，而字符串解析是 SymPy 最慢的事之一 ✗。

### F4 — 2026-11-09 · 拖动时每一帧都在重算判定

- **症状**：在"实例"作用域下拖动一个点 ✓，每帧要 5–17 ms ✓（图形越大越慢 ✓）。
- **根因**：`move_point` 调的是 `evaluate()` ✓ —— 精确路径 + 数值路径 ✓ —— 还要 `_changed()` ✓ → 窗口**整个刷新** ✓ → **判定重算** ✓。
- **修法**：拖动期间**只走数值路径** ✓，只发"便宜的那条通知" ✓，**判定松手时才算** ✓ —— 判定是关于**说法**的 ✓，而说法不是在某个像素上做的 ✓。
- **动作**：**"图变了"和"点动了"是两种事** ✓。混在一起，就等于让每一帧都做全部的活 ✓。
