# T047 —— 可拖动的 HTML 导出（一页纸，几 KB）

**状态**：已实现
**负责人**：Agent
**规格**：[`docs/spec.md`](../docs/spec.md) D20（一份原语，多个后端）
**依赖**：T018（原语列表）、T046（数值路径）
**涉及层**：应用

## 问题

一张静态图对学生说"这是真的"；**一张能拖的图说的是"你看，它一直是这样的"**。
所以要把图导成一个网页：学生能拖动点，图形跟着变。

难点只有一个：**怎么让小**。显而易见的做法是嵌一个几何引擎 —— 那页面就是两兆。

## 做法

**不嵌引擎。** 内核本来就把图按**数值**算一遍好上屏，而那一条路径全是算术 ——
所以页面拿到的是**每个对象一个 JS 函数**，由内核的同一条精确表达式打印出来；
再加一百来行画图代码和一张 SVG。一个图就是几 KB 的公式。

具体：

1. **公式**：`sympy → JavaScript` 的打印器（四则、`sqrt`、`Abs`、`acos`、`pi`），
   并且用 **CSE**（公共子式提取）只打印一次 —— 外心的分母在一个对象里出现六次，
   不提就是十几 KB 的重复。
2. **画**：页面里的 SVG 每个对象带 `id`；拖动时按 id 原地改 `cx/cy/x1/y1/r/points`，
   不重建 DOM。直线按 Cyrus-Beck 裁到页面内（和 SVG 导出同一套），标签从图形中心往外放。
3. **拖动**：`pointerdown` 命中自由点（18 px 内）→ `pointermove` 改坐标 → 重画。
   没有自由点就没有可拖的东西，导出会拒绝。
4. **教学功能**（第一版）：拖动 · **显示/隐藏标签** · **回到原位** · **构造步骤**（可折叠）。

## 验证：不是"看起来对"

页面里的数字是**第三个消费者**（屏幕、SVG、网页），而它出错是**安静的** ——
一个符号、一个括号，页面就画一张不是内核算出来的图。

所以 `tests/integration/test_html_page.py` **真的用 Node 跑那段 JS**，
把每个对象的值和内核的数值路径逐个比（1e-9）。
没有 Node 的机器上跳过 —— CI 不需要它，因为页面就是从同一批表达式生成的。

**实测：三张图（外心、切线、三个心）全部一致。**

## 大小

| 图 | 页面 |
|---|---|
| 三角形 + 中点 + 外心 + 外接圆（7 个对象） | **11.6 KB** |

（一个外接圆的外心表达式原样打印是 8 KB；CSE 之后是一个 `const`。）

## 交付物

- `src/geobench/app/export_html.py`：`html_source` / `js_expression` / `write_html`
- `src/geobench/app/window.py`：文件 → 导出 → **导出 HTML（可以拖动）**
- `tests/app/test_html_export.py`（12 项：自包含、大小、id、转义、拒绝、打印器）
- `tests/integration/test_html_page.py`（Node 对拍）
- `docs/tests.md`：多了一个后端

## 已知限制

- **弧 / 扇形 / 测量**不能拖（它们的位置/角度由内核算，还没移植到页面）。
  这种图导出会**拒绝**并建议用 SVG —— 比"一半会动一半不会"诚实。
- 页面**不做判定**。它不是内核，也不是判定的地方；它只画、只动。
- 视图固定（拖动时不重新缩放）：一张会跳大小的图比一张画到边上的图更难读。
- 没有箭头/自动排版/导出成图片；那些是下一步。
