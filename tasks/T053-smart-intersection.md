# T053 —— 点击交点就是交点（线·线 / 线·圆 / 圆·圆）

**状态**：已实现
**负责人**：Agent
**规格**：`docs/spec.md` §5（交点算子）
**依赖**：T026（两圆交点）、T029（交点点出交点）
**涉及层**：数值路径 · 应用

## 问题

用户：「**现在交点的选择还是不够智能**……鼠标足够精确点向交点时就直接产生交点，
而不是『圆上的点』或者『线上的点』。」

量出来是三个问题：

1. `numeric.intersection_near` **只找线·线**交点 —— 线·圆、圆·圆根本不在候选里，
   于是一定落到"圆上的点 / 线上的点"；
2. 它返回**第一个**在容差内的交点，不是**最近的**；几条线挤在一起时点哪个都一样；
3. 点工具先看圆、再看线，**不看哪个更近**；而且线段被当成**支撑直线**，
   线段的延长线上的"交点"也算数。

## 做法

### ① 交点是一个有类型的东西

`numeric.Crossing`：`kind`（`lines` / `line_circle` / `circles`）、两个对象、
数值坐标、**分支号**、到光标的距离。`operation()` 给出建它的算子与参数：

| 种类 | 算子 | 参数 |
|---|---|---|
| 线·线 | `point.intersect_lines` | `(线, 线)` |
| 线·圆 | `point.intersect_line_circle` | `(线, 圆, "0"/"1")` |
| 圆·圆 | `point.intersect_circles` | `(圆, 圆, "0"/"1")` |

**分支号必须和算子自己的编号一致**，否则点右交点会得到左交点。线·圆沿用算子的
参数化（`P0` 是直线上离原点最近的点，方向 `(b,-a)`），圆·圆沿用算子的
`(bx ∓ dy·s, by ± dx·s)`。两条分支都算出来，选离光标近的那条。

### ② 只算画出来的部分

线段不是它的支撑直线：两个线段的延长线在屏幕外相交，那不是纸上的交点。
`_on_drawn_part` 把线·线和线·圆候选按线段参数 `t ∈ [0,1]`（加一点像素余量）过滤。

### ③ 精确点在交点上时，交点优先

点工具的顺序改成：

1. 找最近的交点（容差 8 px）；
2. 找**最近的可附着对象**（线 / 线段 / 圆，同一个容差、同一个距离度量）；
3. 若交点与光标的距离 ≤ 对象距离 + **4 px 磁吸**，建交点；否则附着到对象；都没有就放自由点。

所以：点在交点上 → 交点；沿圆走开 5 px → 圆上的点；沿直线走开 5 px → 线上的点。
相切（只有一个交点、算子拒绝二选一）时回落到"圆上的点"，不产生一个注定无值的对象。

pytest tests/unit/test_crossings.py -q      # 7 项：种类、最近、分支、线段范围、隐藏

## 非目标

- 射线与多边形边的交点（射线不是"线"参数；等有需要再加）；
- 多条线共点时选择"用哪两条"（坐标相同，选最近的一对即可）；
- 相切点用专门的算子（现在附着到对象，语义相同）。
