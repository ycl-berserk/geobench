# T025 —— 画板即时呈现

**状态**：已实现
**负责人**：Agent
**规格**：[`docs/plan.md`](../docs/plan.md) §7
**依赖**：T020b
**涉及层**：图元 · 应用

## 目标

用户原话：**"现在这个软件好卡……我要求画板的速度要达到即时呈现效果，不能有延迟"** ✓。

问的是"是不是 Python 脚本本身的速度慢导致的" ✓ —— **不是** ✓。慢的是**画板这一层**，而且慢得离谱：**几十个对象的图，重画一次要几分钟** ✓。

## 怎么查出来的

不猜 ✓，量 ✓。把一帧拆成几块分别计时 ✓：

| 部件 | 44 个对象时 |
|---|---|
| 精确求值 | 0.11 ms ✓ |
| 数值求值 | 0.06 ms ✓ |
| 出图（图元层） | **卡住不出来** ✗ |
| 判定 | 0.00 ms（有缓存 ✓） |

再把卡住的那一块拆开 ✓ —— 用一个后台线程跑它 ✓，六秒后把线程的栈打出来 ✓：

```
figure_primitives → _label_offset → numeric_coords → free_symbols → FIELD.coerce → sympy.parse_expr
```

**每画一个标签，就要问每个点一次坐标；而问坐标在缓存缺失时会去解析符号表达式** ✗。

## 根因（三条，叠在一起）

1. **放置值是有理数，数值路径读不了** ✓ —— 拖动过的点，放置值是 `"101/100"` ✓，而数值路径用 `float(placement)` 读 ✓ —— 读不了就当这个点"没有值" ✓，**所有派生对象跟着 undefined** ✓。
2. **图元层因此回退到精确路径** ✗ —— 违反决策 D18 ✓（屏幕只该看数值路径 ✓）。回退的代价是 SymPy 的表达式解析 ✓。
3. **精确路径反复解析同样的字符串** ✓ —— 点的坐标和放置值每次求值都要重新 `sympify` 一次 ✓。

于是：**O(n²) 次字符串解析** ✓ —— 几十个对象几分钟 ✓。

## 交付物

- **数值路径读有理数** ✓（`numeric.placement_float` ✓）
- **图元层只读数值缓存** ✓，没有值就不画 ✓，**绝不回退到精确路径** ✓
- **质心每张图算一次** ✓，不是每个标签算一次 ✓
- **精确路径记住解析过的字符串** ✓（`SympyField._parse` ✓）
- **拖动只走数值路径** ✓：构造没变 ✓，精确路径无事可做 ✓（决策 D18 ✓）；判定**松手时才算** ✓
- **两条新的门禁** ✓（`tests/perf/test_budgets.py` ✓）：出图 ✓、拖动一帧（带出图）✓；而且基准图形的放置值改成了**有理数** ✓
- 测试 `tests/app/test_drag.py` ✓（3 个用例 ✓）：移动和修改是两条通道 ✓、有理数放置值之后整张图仍然完整 ✓、拖动确实带着画面走 ✓

## 结果

| 场景 | 修之前 | 修之后 |
|---|---|---|
| 出图（44 个对象） | 几分钟 | **0.11 ms** |
| 拖动一帧（44 / 124 / 244 个对象） | 几分钟 | **3.7 / 4.9 / 6.9 ms** |

拖动一帧现在只剩：**一次数值求值 + 一次重画** ✓。
