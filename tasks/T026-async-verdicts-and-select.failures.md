### F1 — 2026-11-09 · 判定跑在界面线程上

- **症状**：**画一个圆要等 2 秒才能显示** ✓。
- **根因**：画圆在核心里只要 1.7 ms ✓ —— 2 秒在**判定**上 ✓。判定按设计就要几秒 ✓（计划 §7 ✓），但它跑在界面线程上 ✗，而画板的重画排在它后面 ✗。
- **修法**：判定搬到后台线程 ✓，算的是图的副本 ✓，结果用信号送回来 ✓，过期的丢掉 ✓。
- **本该拦住它的门禁**：**没有** ✗ —— 门禁量的是内核 ✓，量不到"界面线程上排着队" ✓。
- **动作**：**慢的东西必须离开界面线程。** 计划里写着"异步" ✓，但没人实现 ✓ —— 计划上的词不算是实现 ✓。

### F2 — 2026-11-09 · 后台的结论没记住

- **症状**：证明在后台跑 ✓，但**每次改动都要重证一遍** ✓ —— 判定面板总是慢半拍 ✓。
- **根因**：证明跑在图的**副本**上 ✓ → 结论落在副本的缓存里 ✓ → 活着的图不知道 ✓ → 下次请求又要重算 ✓。
- **修法**：`absorb_verdicts` ✓ —— 把副本的结论搬回活着的图 ✓。
- **动作**：**后台算出来的东西要能留下来**，否则后台只是把活儿重做一遍 ✓。

### F3 — 2026-11-09 · `_changed()` 丢了（T023b 的回归）

- **症状**：加一个点之后，**步骤面板不再更新** ✓（画板还在重画 ✓，所以不显眼 ✓）。
- **根因**：T023b 做原子构造时重写了 `add_free_point` ✓ 和 `construct` ✓ —— 重写时**把 `self._changed()` 弄丢了** ✓。
- **修法**：补回来 ✓。
- **本该拦住它的门禁**：**没有** ✗ —— 所有测试都直接调 `window.refresh()` ✓，所以从来没有问过"窗口自己知道吗" ✓。
- **动作**：**测试要问用户问的问题。** 用户不会去调 `refresh()` ✓ —— 他加一个点 ✓，然后看步骤表有没有长 ✓。现在有这条测试了 ✓。

### F4 — 2026-11-09 · 选中的行被冲掉

- **症状**：用"选择"工具点中一个点 ✓，步骤面板**没有跳到那一行** ✓。
- **根因**：鼠标一松手就"结算"整张图 ✓ —— 哪怕只是点了一下 ✓ —— 结算会重建步骤面板 ✓ → 当前的行没了 ✓。
- **修法**：① 拖过才结算 ✓；② 重建步骤面板时**记住自己在哪一行** ✓，重建完跳回去 ✓。
- **动作**：**重建一个面板，要记住读者的位置。** 一个把读者丢回去的面板，比没有更糟 ✓。
