# T044 —— 两个 DSL 的洞：同名重定义、坐标支持精确表达式

**状态**：已实现
**负责人**：Agent
**规格**：[`docs/dsl-spec.md`](../docs/dsl-spec.md) §2.1 / §2.1.1
**依赖**：T043（评测集把它们顶出来的）
**涉及层**：DSL · 内核

## 问题

T043 的 22 道真实题面里，有两道**解析不了** —— 不是模型笨，是我们的语言缺两块：

```
D = 旋转(B, 60, A)
D = 位似(D, 3/5, A)        # 名字 'D' 已经用过了
```

```
点 A(0,0) B(4,0) C(2, 2*sqrt(3))   # 坐标后面应该有右括号
```

- **同名重定义**：GeoGebra 允许同名替换，模型想「先旋转、再位似」用同一个名字。
  我们一次都不许 —— 于是模型**没有写法**。
- **坐标只收有理数**：等边三角形的第三个顶点是 `2√3`，写不出来。
  内核是精确的，`sqrt(3)` 本来就该支持 —— 这是**语法**的限制，不是精确性的限制。

## 做法

### 一、坐标是精确的数，可以写成表达式

`点 A(0,0) B(4,0) C(2, 2*sqrt(3))` 现在成立：

- 支持 `+ - * /`、括号、`sqrt(...)`；小数按有理数读（`2.5` 就是 `5/2`）。
- **只有 `sqrt`，没有变量**：`sqrt(a)` 被拒绝（坐标是数，不是程序）。
- `placement` 保留**精确的字符串**（`"2*sqrt(3)"`），数值路径用
  `FIELD.coerce` 求值（`numeric.placement_float` 多了这一条兜底）。

错误信息可照着改：

- `sqrt(a)` → 「'a' 不是数 —— 坐标里不能有字母，只能用数字、sqrt(3)、1/2 这样的写法」
- `log(2)` → 「坐标里只有 sqrt，没有 log」

### 二、一个名字可以定义两次

```
点 A(0,0) B(5,0)
E = 旋转(B, 60, A)
D = 中点(A, B)
D = 位似(E, 3/5, A)     # 替换掉上面那个 D
```

- 后一次**替换**前一次；**依赖这个名字的对象自动跟着新的定义**（依赖的是 id）。
- **绕回自己的定义被拒绝**：`D = 位似(D, …)` 没有答案。
  错误信息直接教写法：「中间结果换个名字：先写 E = …，再写 D = …(E, …)」。
- 间接环也拒绝：`E = 中点(D,A)` 而 `D = 中点(E,B)`。
- 实现要点：`Figure.replace_node` **会 bump 版本号** —— 因为自由点从不重算，
  不 bump 的话，依赖者会抱着**旧定义**算出来的表达式不放。

## 实测

| | 之前 | 之后 |
|---|---|---|
| 真实题面 | 21/22 | **22/22**（数值条件 5/6 → **6/6**） |
| 契约用例 | 9/9 | 9/9 |

**诚实说明**：紧接着的第二次录制是 **21/22** —— 同一道「平行四边形」，
模型这次又写了自引用（被拒绝后重试成了别的写法）。**模型是随机的，单次运行有波动**；
这两块补齐之后，两类**解析失败**都消失了，剩下的是模型自己的稳定性问题。

## 已知限制

- 坐标里**只有 `sqrt`**。以后要 `sin`、`pi`、`root(3,2)` 再说 —— 现在没有题面需要。
- 重定义**不检查类型变化**：把点重定义成线是允许的，用到它的对象会在求值时
  报错（而不是在解析时）。GeoGebra 也是这样（依赖者变成 undefined）。
- 重定义**不留历史**（不像 GeoGebra 的构造协议那样可以回退）——
  撤销由应用的 undo 管，DSL 本身只保留最终图。
