# T023b 失败记录 —— 一个被拒绝的构造把整张图毒掉了

按 `docs/ai-workflow.md` §6 留档。

---

### F1 — 2026-11-09 · `construct` 不是原子的

- **症状**：用"直线"工具在**同一个点上点两下** → `StateError: cannot build a line through a single point twice` → 之后**每一次重画都崩**，程序死 ✓。
- **根因**：`construct` 先把节点**加进图** ✓，再 `evaluate()` ✗ —— 评估失败时**节点留在图里** ✓ 而且**没有缓存** ✓ ✓。于是下次 `evaluate` 又失败 ✓，每次 `paintEvent` 也失败 ✓ → 异常从 Qt 事件里逃出来 → **进程结束** ✓。
- **修法**：构造**全有或全无** ✓ —— 失败就 `_restore` 回快照 ✓ ✓。
- **本该拦住它的门禁**：**没有** ✗ —— 随机会话 ✓ 也没撞到 ✓（它随机选对象 ✓ ✓，很少选同一个两次 ✓ ✗）。
- **动作**：**"拒绝"必须什么都不留下。** 半成品比没有更糟 ✓ —— 它不但没用 ✓，还让整张图不再能用 ✓。

### F2 — 2026-11-09 · 图元层没接住 `KeyError`

- **症状**：同一场崩溃里，`paintEvent` 报 `KeyError: 'line'` ✓。
- **根因**：`figure_primitives` 的保护只接 `(StateError, TypeError, ValueError)` ✗ ✓ —— 而"节点没有载荷"是 `KeyError` ✗ ✓。
- **修法**：保护扩到 `KeyError` 和 `ArithmeticError` ✓ ✓（"这个对象没有值"的所有样子 ✓）。
- **本该拦住它的门禁**：上一次 T023 修的就是"图不崩" ✓ —— 但只修了**我以为**会出现的异常 ✓。
- **动作**：**保护要按"会出什么"写，不是按"我想到什么"写。** 兜底的地方，宁可宽一点 ✓。

### F3 — 2026-11-09 · 同一个对象被当成两个参数

- **症状**：直线工具第二次点同一个点时 ✓ 又收了一次 ✓ → `["A","A"]` ✓。
- **修法**：**跟上一个刚选的一样**就忽略 ✓ ✓（双击 ✓ 不是"第二个参数" ✓）。
- **动作**：**点击是"选一个对象"，不是"记一次"** ✓ —— 同一个东西连着点两下 ✓，人手的意思一定是"手抖了" ✓。

### F4 — 2026-11-09 · 补原子性时把撤销栈改成了每次两条

- **症状**：撤销测试红 ✓ —— 加三个点 ✓，撤两次还剩两个 ✗ ✓。
- **根因**：`push_undo()`（旧）没删 ✓ ✓，又加了 `push_undo_past(before)` ✓ → 每次操作进两条 ✓ ✗。
- **修法**：删掉旧的 ✓ ✓。
- **本该拦住它的门禁**：撤销测试 ✓（当场红了 ✓）。
- **动作**：**改一条路的时候，把旧的那条擦掉。** 两条路都留着，账就记重了 ✓。

### F5 — 2026-11-09 · 斜率/方向不接受线段

- **症状**：`斜率(线段AB)` 报 `segment is not a line` ✓。
- **根因**：契约里"线"这一类**允许线段** ✓（`_check_argument` ✓ ✓ —— "BC 上的垂足"对线段和直线是一个意思 ✓），但算子用的是 `ctx.line()` ✗ 而不是 `ctx.as_line()` ✗ ✓。
- **修法**：改用 `as_line` ✓ ✓。
- **动作**：**契约说"可以"的东西，算子就得真的收。** 两处对"线"的理解不一致 ✓，用户看到的就是"明明能选，选了却报错" ✓。
