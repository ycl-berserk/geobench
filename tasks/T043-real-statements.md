## 问题

用户说：

> 现在 ai 还是没有办法根据我的自然语言进行绘图，这中间肯定是很困难的，
> 应该没有你想象的这么简单。我觉得你需要查阅一下类似的 ai 产品是怎么解决相关问题的。

**这话是对的，T041 的结论被我夸大了。** 那 8 道题是**我们自己写的**、措辞是我们定的、
每道只试一种说法，而且规范里还给了模型一张「稳坐标」表。
它测的是**契约**（模型学没学会我们的语言），**不是**「产品能不能接住任意题面」。

## 先量

`scripts/measure_conditions.py`（**手动跑真模型，不进 CI**）：6 道**真题面**，
带数值条件，检验图**满不满足题面的条件**。

| 题面 | 结果 | 为什么 |
|---|---|---|
| 等腰三角形 AB=AC + 中点 + 高 | ✓（第一次）/ ✗（第二次） | **靠那张「稳坐标」表**蒙对的 |
| 直角三角形 ∠A=90°、AC=4、BC=3 + 垂足 | ✗ | 模型**不会算** 3-4-5：画成 AB=3、AC=4、BC=5，**边搞反了** |
| 外接圆 + 圆外点 OP=5 + 切线 | ✗ | **偷偷替换**：把 P 放在圆上（OP=5 不成立），切线成了圆上那点的切线 |
| 平行四边形 AB=5、AD=3、∠DAB=60° | ✗ | **解析失败**：同一个名字 `D` 定义了两次 |
| 等边三角形 边长4 + 外接圆 + 内切圆 | ✗ | **解析失败**：坐标写成 `2*sqrt(3)`，我们的 DSL 只收有理数 |
| 对照组：画一个三角形 | ✓ | 没有条件就没有难度 |

**1/6 ~ 2/6**（两次跑，模型有随机性；n 太小，**区间 1/6–2/6**）。

**失败的全是"条件"，不是"语法"。** 这句话是这一页的结论。

## 顺带挖出两个 DSL 的洞

1. **同名重定义**：模型写 `D = 旋转(B,60,A)` 再 `D = 位似(D,3/5,A)` ——
   GeoGebra 允许（同名即替换），我们报「名字 'D' 已经用过」。
   模型想要的是**分步构造**，我们的 DSL 只能一步到位。
2. **坐标只收有理数**：`C(2, 2*sqrt(3))` 写不出来。内核是精确的，
   `sqrt(3)` 本来就该支持；这是**语法**的限制，不是精确性的限制。

## 调研：同类产品怎么做的

四个模式，各有各的用处：

### ① 学术（几何题求解）：**形式化几何语言**

Inter-GPS、PGPS9K、GeoQA/UniGeo、GeoX（ICLR 2025）、GOLD（NAACL 2024）。

- **关键结论**：GeoX 报告「**形式语言比自然语言更有效**，Geometry3K 的 Completion +2.9%」。
- **两阶段分解**：Interpreter（把图/题面变成**符号化的形式文字**）→ Solver（在这些文字上推理）。
- **符号层与图元层分开**：GOLD 把「符号（哪些字母）」和「几何基元（什么形状、什么关系）」
  **分别处理**，再转成自然语言。
- **评测集**：Geometry3K（3001 道，带图）、UniGeo（**9543 道中国高中教材题**）、
  GeoQA（4998 道中国初中题）、PGPS9K、GeoEval（24912 道）。

> **对我们的意义**：我们的架构（模型 → DSL → 确定性内核）**就是**这一派，选对了。
> 缺的是：把「符号」和「图元」分开、把流程拆成两段、以及**用真实题面做评测**。

### ② 商业图示产品（Miro / FigJam / Excalidraw）：**模型不画，引擎画**

Excalidraw 的 text-to-diagram 公开了原理：**prompt → Mermaid → 图**。
模型只产出**声明式规格**，坐标、连线、标签位置**全部由引擎负责**。

> **对我们的意义**：**我们现在让模型去编坐标，方向就是错的** ——
> 而且规范里那张「稳坐标」表就是这错误的拐杖。
> 模型应该写**关系**，引擎解出坐标。

### ③ CAD 参数化约束求解（SolveSpace / CAD Sketcher）：**约束 = 方程**

未知量 = 坐标，方程 = 约束，数值牛顿法迭代求解；
成熟的状态分类：**欠约束 / 完全约束 / 冗余（但一致）/ 不相容 / 不收敛**；
而且「**初始猜测决定选哪一个解**」。

> **对我们的意义**：这就是「锐角三角形、AB=AC、∠A=90°」该走的地方。
> 我们的 spec §8 早就规划了 `geo_solve`（约束求解与变体）—— **只是从来没建**。

### ④ 视觉闭环（Render-in-the-Loop ECCV'26 / IntroSVG CVPR'26 / TikZ 的"不完美验证"）

- Render-in-the-Loop：「现有范式是**开环的盲画**……我们把渲染结果喂回模型，让它**边看边画**」。
- IntroSVG：Generator-Critic —— 起草 → 渲染成 PNG → **批判**（打分 + 可执行的修改建议）→ 改 → 再渲染。
- TikZ 的那篇：「输出以视觉为主时，正确性**无法形式化**，只能靠**不完美验证器**（LLM/VLM 评估）」。

> **对我们的意义**：我们现在是**开环**的：模型写代码、内核查几何，**没有人看过那张图**。
> 而「像不像」恰恰是内核判不了、老师第一眼就看出来的东西。

### 顺带：我们的正面对手 GeoGebra 也不做「NL → 图」

GeoGebra Discovery 做的是**给定一张图 → 发现/证明定理**（Prove / ProveDetails /
Discover，301 道测试定理能证 255 道），不是「说一句话 → 出图」。
所以「一句话出图」这件事，**整个市场都还没做好**；市面上的答案是 ②（模型写规格、引擎画）。

## 思路（按杠杆/成本排序）

| # | 思路 | 消灭的是什么 | 代价 |
|---|---|---|---|
| 1 | **模型不写坐标，引擎解约束**：DSL 增「约束」（AB=AC、∠A=90°、锐角…），内核加约束求解器（数值牛顿 + 自由度分析 + 不相容/不收敛的分类） | 「模型不会算」这一整类失败 | 大（spec §8 从未实现） |
| 2 | **把图放进回路**：渲染 PNG 回喂模型（要视觉模型）；或至少让内核报**版面事实**（包围盒、标签重叠、最小角、出界）——「标签位置」正是「像不像」的核心 | 「没人看过那张图」 | 中（小步：先内核报事实，再接视觉模型） |
| 3 | **两阶段 + 符号/图元分开**：模型先出「场景描述」（名字 + 关系），再落成构造 | 模型的弱项（编坐标）和强项（理解题面）混在一起 | 中 |
| 4 | **范例从题库里挖**：不手写 5 个例子，而是从题库检索最相近题目的现成图当 few-shot（Excalidraw 的 MCP 模式：模型看的是**你的上下文**） | 「范例比规则管用」的规模化 | 小～中（要题库） |
| 5 | **评测集换成真实题面**：UniGeo（9543 道中国高中教材题）/ GeoQA / Geometry3K 是现成的分布，而且**带参考图**，可以做「和参考图比」的度量 | 「自己的 9 句话」这个偏差 | 小（下载 + 清洗 + 期望要写） |
| 6 | **补两个 DSL 洞**：同名重定义（GeoGebra 允许）、坐标支持精确表达式（`sqrt(3)`） | 两次解析失败 | 小 |
