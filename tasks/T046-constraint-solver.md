# T046 —— 约束求解：让内核算坐标，且只接受精确解

**状态**：已实现
**负责人**：Agent
**规格**：[`docs/spec.md`](../docs/spec.md) §8、[`docs/dsl-spec.md`](../docs/dsl-spec.md) §2.1.2
**依赖**：T044（精确表达式坐标）
**涉及层**：内核 · DSL

## 问题

条件有时是**一组**，只能靠算：

```
画一个三角形，三边 5、6、7
```

模型不会算（试探的结果：它会把边搞反、或者退回"摆"几个整数）。而 spec §8 早就写了
`geo_solve` 的契约 —— **数值优先，符号验证，通不过的解丢弃** —— 从来没实现。

## 做法

`约束` 语句（两种写法，一个意思：一个必须为零的表达式）：

```
约束 垂直(AB, AC)            # 判定
约束 长度(AB) = 5            # 等式
约束 角度(B, A, C) = 40
约束 长度(AB) = 长度(AC)
```

求解在**整份脚本读完之后**（约束可以提到它引用的对象之前）：

1. **数值**：未知量 = 自由点的坐标，方程 = 上述表达式；Levenberg-Marquardt，
   每个残差按它自己的梯度归一（长度和面积不是同一个量级）。
2. **只动尽量少的点**：先试"只动最后声明的点"，再试最后两个……
   因为 `|AC| = 3` **不在乎是 A 动还是 C 动** —— 把三个点都挪一点，
   3-4-5 会变成三个无理数。这条是实测出来的（第一版就是这么坏的）。
3. **精确**：每个坐标先试分母 ≤ 1000 的有理数，再试小根号的组合，
   然后**精确验证**全部约束。组合按"最简单优先"试，验证决定一切。
4. 通不过 → **拒绝**，并说清是哪一条、以及"用『旋转』『位似』一步步构造会更好"。

## 实测

| 例 | 结果 |
|---|---|
| `距离(A,C)=3`、`距离(B,C)=4`（A=(0,0), B=(5,0)） | **C = (9/5, 12/5)** ✓ 有理 |
| `长度(AB)=5`、`AC=6`、`BC=7` | **C = (6/5, 12√6/5)** ✓ 代数（靠 T044 的 sqrt 坐标） |
| `垂直(AB, AC)` | **C = (0, 1)** ✓ 关系约束（多项式，好条件） |
| 顶角 40° | **拒绝**（无精确坐标）—— 用 `旋转` |
| `AB = AC`（最近解） | **拒绝**（最近解是无理数）—— 用 `圆上的点` |

**这是一把手术刀，不是万用工具**：单个条件几乎总有更好的构造写法；
它的价值在"几个条件同时给定、而且解恰好精确"。

## 已知限制

- **最近解必须精确**。解存在但最近点是无理数时（`AB = AC` 就是），会拒绝 ——
  宁可拒绝，也不把"一个有理数近似"当成答案。
- 角度**测量**约束（`角度(...) = 40`）的梯度在初始位置常常指向侧面，
  求解器会爬到远处的一个合法解；右角请写 `垂直(...)`（多项式）。
- 只解**自由点**坐标；不改构造。要"构造也变"，那是另一件事（约束求解 + 构造搜索）。
- 求解是**局部的**：从当前图出发找最近的解。离得太远（> 50 倍图幅）会拒绝。
