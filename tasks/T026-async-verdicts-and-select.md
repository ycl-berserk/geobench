# T026 —— 判定不再挡屏幕；加"选择"工具

**状态**：已实现
**负责人**：Agent
**规格**：[`docs/plan.md`](../docs/plan.md) §7
**依赖**：T025
**涉及层**：应用

## 目标

用户原话：**"现在还是卡，而且还是卡的要死，画一个圆都要等 2 秒才能显示"** ✓，
以及 **"我建议你加上'选择'的功能，要不然无法精确选中某个点"** ✓。

## 慢在哪

量下来 ✓：画一个圆在核心里只花 **1.7 ms** ✓（首次 74 ms 是 SymPy 的预热 ✓）✓ —— **核心里没有 2 秒** ✓。

那 2 秒在**判定**上 ✓：

- 判定按设计就要几秒 ✓（计划 §7：**"判定判真（proved，常见） ≤ 2 s"** ✓ —— 那是符号化简的代价 ✓）；
- 它跑在**界面线程**上 ✗；
- 而画板的重画是**排队**的 ✗ —— 所以**圆要等证明算完才出现** ✓。

所以从外面看是"画圆很慢" ✓，其实是"画圆要等证明" ✓。

## 交付物

- **判定搬到后台线程** ✓：算的是图的**副本** ✓（用户可以一边拖一边改 ✓），算完了用信号送回界面线程 ✓，**过期的结果丢掉** ✓
- **画面不等判定** ✓：表格在证明跑着的时候显示旧结论 ✓，标题写着"判定中……" ✓
- **后台找到的结论要记住** ✓（`absorb_verdicts` ✓）—— 否则同一个说法每次改动都要重证一遍 ✓
- **"选择"工具** ✓（工具栏第一个 ✓，一个箭头 ✓）：点一下**精确选中** ✓（点、线、线段、射线、圆、多边形 ✓），选中的对象**画成强调色** ✓，步骤面板**跳到那一行** ✓，**Delete 键删掉它** ✓，状态栏说选中了什么 ✓
- 顺带修好一个**我自己的回归** ✓：T023b 做原子性的时候把 `_changed()` 弄丢了 ✓ → 加一个点之后**步骤面板不再更新** ✓（画板还在重画 ✓，所以不显眼 ✓）—— 测试没抓住 ✓，因为它们都直接调 `window.refresh()` ✓
- 测试 `tests/app/test_select.py` ✓（4 个用例 ✓）+ `test_the_window_notices_a_change` ✓

## 关键做法

**"证明很贵"是产品的性质，不是缺陷。** GeoGebra 不证明任何东西 ✓，所以它没有这个问题 ✓；我们要证明 ✓ —— 所以证明必须**离开界面线程** ✓。

**后台算的是副本。** 证明读到一张正在变的图 ✓，那它证明的就不是任何东西 ✓。

**点一下和拖一下不一样。** 之前鼠标一松手就"结算"整张图 ✓ —— 哪怕只是点了一下 ✓ —— 于是每次点击都重建一次步骤面板 ✓，把刚选中的行冲掉 ✓。
