### F1 — 2026-11-08 · 级联删点的顺序全错

- **症状**：`node 'A' is used by M; remove the dependents first` ✓ —— 删 A 删不掉 ✓。
- **根因**：两处都是顺序 ✓：
  1. 先删**对象**再删**断言** ✓ —— 而断言引用着对象 ✓ → 被拒 ✓；
  2. 判断"这个东西能不能删"时 ✓ 我看的是**待删集合** ✓ 而不是**真正的图** ✓ —— 于是 A（还被 M 用着 ✓）看起来"没人用" ✓ → 先删 A ✓ → 被拒 ✓。
- **修法**：顺序改成"先断言、再对象" ✓；"能不能删"改成**读图** ✓ —— 一个人被删掉了，才真的不在了 ✓ ✓。
- **本该拦住它的门禁**：新写的删除测试 ✓（它当场就红了 ✓）。
- **动作**：**"准备删"和"已经删"是两回事。** 集合里放着的东西还在图里 ✓ —— 读集合等于假设它们已经没了 ✓。

### F2 — 2026-11-08 · 补级联的时候把方法截断了

- **症状**：mypy 报"`self` 未定义" ✓、"语句不可达" ✓。
- **根因**：我把 `remove_node` 的方法体换掉时 ✓ 在里面插入了 `@staticmethod` ✓ —— 于是原来方法末尾的 `self.evaluate()` / `self._changed()` 变成了新方法的**死代码** ✓ ✗。
- **修法**：把这两行还给 `remove_node` ✓。
- **本该拦住它的门禁**：mypy ✓（它抓到了 ✓）。
- **动作**：**在方法中间插入新方法，等于把方法砍成两截。** 加方法要加在**方法的边界之外** ✓。

### F3 — 2026-11-08 · `currentItem()` 的返回类型骗了 mypy

- **症状**："语句不可达" ✓ —— `if item is None: return` 被判成永远不成立 ✓。
- **根因**：PySide6 的类型标注说 `currentItem()` 返回 `QListWidgetItem` ✓（非可选 ✗），实际上可能是 `None` ✓。
- **修法**：改用 `selectedItems()` ✓（返回列表 ✓）✓ —— 空列表就是"没选" ✓ ✓。
- **动作**：**类型标注和运行时不符的时候，换个写法比加 `# type: ignore` 好** ✓ —— 那个"谎"会跟着代码走很久 ✓。
