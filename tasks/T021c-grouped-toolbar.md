## 目标

用户的要求原话：**"把已有的工具都做好（可以参照 GeoGebra 的方式把类似的工具放在一个选项卡里面），确认都可以在界面当中展现"** ✓。

查下来：**36 个已实现的构造命令，工具栏只有 16 个入口** ✗ —— 交点、线段、直线、圆、垂足、切线、平行线、垂线、极线、顶点、仿射比、正多边形、平移/旋转/位似/镜像、面积/周长/半径/斜率/方向，**全都没有入口** ✓。

- **参数模型** ✓：工具按算子真正的参数类型收东西 ✓ —— 点 ✓、线 ✓、线段 ✓、圆 ✓、多边形 ✓、数字 ✓、交点选择 ✓
- **对象拾取** ✓：点（8px ✓）、线/线段/射线（到线的距离 ✓）、圆/弧（到圆周的距离 ✓）、**多边形（点在内部 ✓）**

## 关键做法

**工具栏是生成的，不是手写的。** 手写的列表一定会落后于实现 ✓ —— 这次落后了 20 个 ✓。现在：命令表 ✓ → 算子契约（真正的参数类型 ✓）→ 工具 ✓。

**点击要认"对象"，不只认"点"。** 以前工具只会找点 ✗ ✓ —— 可 `相切(点, 圆)` 要的是**圆** ✓ ✓。所以画板要把点击认成"哪个对象" ✓：到线的距离 ✓、到圆周的距离 ✓、**点在多边形内部** ✓ ✓（多边形是一块区域 ✓，点它的内部就该选中它 ✓，和在别的程序里点形状一样 ✓）。

**几何不在画板里。** 契约测试早就写着：**画板不 import `geobench.evaluate`** ✓（决策 D20 ✓）。所以拾取的几何放进 **图元层** ✓（`primitives.hit_test` ✓），画板只负责把点击换成图形坐标 ✓ ✓。

**多边形成了一个图元。** 原来是"一堆线段" ✗ —— 那就没法"点在内部" ✓ ✓，导出也会画成一堆线 ✓。现在是 `PolygonPrimitive` ✓（顶点 + 是否闭合 ✓）✓，两个后端都画它 ✓ ✓。
