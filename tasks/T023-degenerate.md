# T023 —— 退化的摆放不许崩图

**状态**：已实现
**负责人**：Agent
**规格**：[`docs/plan.md`](../docs/plan.md) §M-B；决策 D15、D19
**依赖**：T015、T019
**涉及层**：判定器 · 渲染 · 应用

## 目标

用户在画板上点了点，程序抛了一串

```
KeyError: 'line'
Error calling Python override of QWidget::paintEvent()
```

—— 画板不再重画，程序死了 ✓。

这一条不是新功能 ✓，是**把"退化"这条规矩真正落实** ✓：GeoGebra 的语义是 —— **一个对象在当前摆放下没有值，它就是 undefined，图还活着** ✓（决策 D19）。前端三条路径（精确 ✓ 数值 ✓ 绘制 ✓）里有一条没守住这条规矩 ✓，就崩 ✓。

## 查出来的是什么

拿随机会话逼出来的（见"做法"）✓ —— 一共 **9 个**真问题：

| # | 问题 | 后果 |
|---|---|---|
| 1 | `circle.through` **丢掉了外心的 `must_be_nonzero` 条件** | 三点共线时圆心变成**复数**，而不是 undefined |
| 2 | 精确路径的兜底 ✗ 把复数直接 `float()` | 抛 `TypeError` ✓ → 从 paint 事件里逃出来 ✓ → **进程结束** ✓ |
| 3 | 绘制层假设每个节点都画得出来 | 一个节点出错 = 整张图不画 |
| 4 | **拖动的坐标是浮点数** | 精确路径拒绝浮点 ✓ → 判定器全挂 ✓（`expression contains a floating point part`）|
| 5 | 撤销不还原**标号计数器** | 撤销后新点重名 ✓ → `node id 'B' already exists` |
| 6 | 关系编号用**数量**推 | 删掉一个关系后重名 ✓ |
| 7 | `load_text` 逐点删除 | 模型拒绝删"还有依赖"的点 ✓ → **打开文件必失败** |
| 8 | 删除点不删引用它的断言 | 模型拒绝 ✓ → 用户删不掉点 |
| 9 | `point_positions` 不认分数 | 拖动之后点全"消失"（命中测试找不到）✓ |

## 关键做法

**"退化"要在三层都守住**：

1. **算子层**：可能退化的算子 ✓ 要**发布条件**（`must_be_nonzero` ✓）✓ —— 借用了别人的计算，就要**把它的前提一起借走** ✓（圆的圆心来自外心 ✓，条件也要来自外心 ✓）。
2. **数值层**：条件不满足 ✓、值不是有限实数 ✓（nan ✓ / inf ✓ / 复数 ✓）✓ → 这个节点标 undefined ✓，**不抛异常** ✓ ✓。
3. **绘制层**：画不出来的节点**跳过** ✓，图的其余部分照画 ✓ ✓。

**摆放必须是精确数。** 内核的规矩是**不许出现浮点** ✓，而摆放会参与符号代入 ✓（判定器读它 ✓）。拖动落在"半个像素"上 ✓ —— 所以摆放写成 `29/20` 这样的有理数 ✓ ✓，显示时再换成小数 ✓。

**随机会话当门禁。** 一条一条想"用户会点哪儿"是想不到的 ✓ —— 所以写了一个随机会话 ✓：随机放点 ✓ 构造 ✓ 撤销 ✓ 重做 ✓ 拖动 ✓ 加断言 ✓ 删对象 ✓ 打开文件 ✓，**每一步之后都尝试画图** ✓。200 个种子 × 30 步 ✓ 全绿之后才收工 ✓ ✓。它现在是正式测试 ✓（16 个种子 ✓，`tests/property/test_editing_never_breaks.py` ✓）。
