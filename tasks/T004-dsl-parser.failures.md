# T004 失败记录

按 `docs/ai-workflow.md` §6 留档。

---

### F1 — 2026-11-06 · 中文关键字被当成了标识符

- **症状**：整个 DSL 解析器一条语句都读不懂，报"无法识别的语句"。
- **根因**：Python 的 `str.isalpha()` 对汉字返回 **True**。词法器里"字母开头就是标识符"的分支先于关键字匹配，于是 `点` 被切成了一个名字。
- **修法**：汉字单独判断（码位区间），**先匹配关键字**，匹配不上才当作对象名。
- **本该拦住它的门禁**：`unit`（DSL 测试）。
- **动作**：记一条原则：**中文 DSL 的词法器必须先试关键字，再试标识符**；而且汉字与 ASCII 必须分两条路径。

### F2 — 2026-11-06 · `△ABC` 被切成一个名字而不是三个顶点

- **症状**："三角形需要三个顶点"。
- **根因**：`ABC` 是连续的字母数字，词法器切成一个标识符；而 `A B C`（带空格）才是三个。
- **修法**：三角形声明接受两种写法——`△ABC` 与 `△A B C`。
- **本该拦住它的门禁**：`unit`。
- **动作**：这条其实是个**好性质**：正因为 `AB` 是一个整体，DSL 里"线段 AB"和"点 A、点 B"才能用同一套记号区分开。

### F3 — 2026-11-06 · 断言解析器把关系词吃掉后又说"缺少关系词"

- **症状**："断言 A B C 共线"报"断言缺少关系词"。
- **根因**：循环里遇到关系词就 `index += 1` 并 `break`，随后用 `index >= len(tokens)` 判断"有没有关系词"——此时 index 已经被推到末尾，判断必然成立。
- **修法**：用独立的 `relation: Token | None` 变量记录关系词，不再拿 index 兼职两件事。
- **本该拦住它的门禁**：`unit`。
- **动作**：记一条原则：**一个变量不要兼职两件事**（既当游标又当标志位）。

### F4 — 2026-11-06 · `=` 是标点，不是符号

- **症状**："断言 AB = AC"报"这里应该是一个名字"。
- **根因**：断言里用 `is_symbol("=")` 判断等号，但词法器把 `=` 归为标点。
- **修法**：两处都判（`is_symbol` 或 `is_punct`）。
- **本该拦住它的门禁**：`unit`。
- **动作**：建议：**词法器的类别要与解析器的预期写成同一份常量**，不要各写各的。

### F5 — 2026-11-06 · "交点"的选择器被丢掉了

- **症状**：解析出来的 `point.intersect_line_circle` 节点只有两个参数，求值时报参数个数不对。
- **根因**：解析器把"第几个交点"单独返回，但建节点时只把 args 写进了节点，选择器**没有落进数据模型**。
- **修法**：选择器作为第三个参数写进 `args`；数据模型允许"字面量参数"（数字、`other`）不是节点引用。
- **本该拦住它的门禁**：`unit`。
- **动作**：这条暴露了数据模型的一个隐含假设：**参数都是节点引用**。现在明确了：参数可以是字面量。

### F6 — 2026-11-06 · "另一交点"的对拍：约定不同，比的不是数学

- **症状**：新算子 `point.intersect_line_circle` 的对拍全败。
- **根因**：内核用**二次公式中根号的正负**给两个根排序；sympy 的 `solve` 用的是另一套顺序。逐位置比较，比较的是**约定**而不是数学。
- **修法**：该算子改用**集合比较**——对拍返回两个交点，内核选出的那个只要是其中之一就算通过；另加测试确认 0 号与 1 号交点不同、且合起来覆盖两个根。
- **本该拦住它的门禁**：`oracle`。
- **动作**：对拍框架新增"集合比较"模式（`SET_COMPARISON`）。**当被测量的东西本身带约定时，就不要拿约定去比。**

### F7 — 2026-11-06 · "另一交点"用符号比较根，慢到超时

- **症状**：`P = AD 与 ⊙O 的另一交点` 让进程挂住超过 10 分钟。
- **根因**：为了判断"哪个根不是 A"，我把两个根与 A 做符号化简。根里带 `sqrt`，化简代价极高。
- **修法**：改用**代数捷径**——二次方程两根满足 `t₁·t₂ = c/a`，已知 A 的参数 `t_A`，另一个根就是 `(c/a)/t_A`，**全程不出现根号**。判断"A 在圆上"则只需判一个**多项式**恒等式（无根号），代价很低。
- **本该拦住它的门禁**：无（表现为**超时**）。
- **动作**：又一次印证 D13 的结论：**能代数地绕开的地方，就不要符号地硬算**。而且"慢"不会让测试变红，只会让 CI 卡住 —— 这类风险只能靠"先量再改"发现。

### F8 — 2026-11-06 · 直线声明的起始位置读错了

- **症状**："直线 l1 = 过 A B" 报"应该出现 直线"。
- **根因**：`直线` 关键字就在第 0 个 token，代码却从第 1 个开始找。
- **修法**：从 0 开始。
- **本该拦住它的门禁**：`unit`。

### F9 — 2026-11-06 · 中点子句在往返后写成了 `A B 中点`

- **症状**：往返测试失败；`AB 中点` 被生成成了 `A B 中点`。
- **根因**：生成器按参数逐个拼接，而 DSL 里两字母名 `AB` 才是线段的写法。
- **修法**：生成器按"两字母合成一个名字"输出。
- **本该拦住它的门禁**：`unit`（往返测试）。
- **动作**：**往返测试是这类 bug 最好的 detector** —— 生成器与解析器是同一个语法的两端，任何一端写错都会被抓到。

### F10 — 2026-11-06 · 用 PowerShell 批量改代码，把中文文件写坏了

- **症状**：`parser.py` 出现大量乱码，语法错误上百处。
- **根因**：用 `Get-Content` / `Set-Content -Encoding UTF8` 做正则批量替换，Windows PowerShell 的默认编码把 UTF-8 中文读成了 GBK 再写回，汉字与 `⊥`/`∥` 等字符被破坏。
- **修法**：整个文件重写。
- **本该拦住它的门禁**：`unit` / `lint`（语法错误立刻暴露）。
- **动作**：**含中文的文件不要用 PowerShell 做批量文本改写**，用编辑工具逐处修改。这条写进 `docs/ai-workflow.md` 的实践约定。
