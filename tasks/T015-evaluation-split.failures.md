### F1 — 2026-11-07 · 编译函数带了全部符号，每帧传 32 万个参数

- **症状**：数值路径实现完，400 个对象的一帧要 **40.5ms** —— 离 16ms 的预算差三倍，比预期慢了一个数量级。
- **根因**：`lambdify(symbols, expr)` 里的 `symbols` 是**全部**自由点符号。400 个点 = 800 个符号，于是每个节点的编译函数都接收 800 个参数，400 个节点每帧就是 32 万次参数传递。
- **修法**：只编译**表达式真正用到的**符号（`expression.free_symbols`）。
- **本该拦住它的门禁**：无（这是**性能**问题，不是正确性问题）。
- **动作**：**先量再改**这条规矩救了这次。改之前量了一次，发现"慢了 25 倍"而不是"慢了一点"，于是立刻知道是参数传递而不是别的。性能问题**只能靠测量发现**——代码读起来完全正常。

### F2 — 2026-11-07 · `copy()` 把缓存丢了，增量全部失效

- **症状**：每改一次图就要重算全部符号表达式。
- **根因**：`Figure.copy()` 走 JSON 序列化，而 `node.cache` **不参与序列化**（这是对的：编译出来的函数没法序列化）。于是副本的缓存是空的。
- **修法**：`copy()` 显式把 `node.cache` 和新的 `Figure.runtime` 带过去 —— 副本是**同一个构造**，缓存当然还有效。
- **本该拦住它的门禁**：无（同样是性能问题）。
- **动作**：**"不序列化"和"不保留"是两件事。** 运行时缓存不该进文件，但**复制**一个构造时必须跟着走。

### F3 — 2026-11-07 · 退化从"抛异常"改成"标 undefined"，把语义改掉了

- **症状**：`geo_construct` 对退化构型不再返回 `degraded` + `errors`，而是 `ok`。
- **根因**：精确路径原来在求值时检查非退化条件，**不满足就抛 `DegenerateError`**。拆路径后，检查挪到了数值路径，而数值路径不抛异常（它只是标 undefined）。
- **修法**：`geo_construct` 改成读 `undefined_nodes(figure)`：有 undefined 对象就报 `degraded`，**原因放在 `warnings` 里**而不是 `errors` 里。
- **本该拦住它的门禁**：`integration`（"退化构型必须报 degraded"）。
- **动作**：这条其实**改对了**，但暴露了一件事：**`error` 与 `degraded` 的分界不是"失败/成功"，而是"该改请求吗"**。退化不是请求写错了，所以它不该进 `errors` —— 进 `errors` 会让 agent 去改一个本来正确的东西。已写进 D15。

### F4 — 2026-11-07 · `no_float` 门禁有盲区：它只拦字面量

- **症状**：数值路径要用浮点，但 `no_float` 门禁只拦**浮点字面量**，不拦 `float(x)` 调用。
- **根因**：门禁的实现是 AST 扫描 `ast.Constant` 里的 float。
- **修法**：把例外改成**按模块名显式列举**（`render` / `style` / `numeric`），每个都写明理由；再加一条**契约测试**：判定器不得 import 数值路径，且判定结果与数值路径是否跑过无关。
- **本该拦住它的门禁**：无。
- **动作**：这是 §11.5 那条"每道门禁都有盲区"的又一次实例。**门禁是下限不是上限** —— 所以补门禁之外，还要补一条**行为契约**（判定与数值路径无关），那才是真正保证精确性的东西。
