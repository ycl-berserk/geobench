# AI 讲题：设计、协议与竞品对照

> 这一页回答三个问题：为什么这样做、市面上谁在做、v1 具体怎么跑。
> 代码在 `geobench/tutor.py`（协议与校验）和 `geobench/app/tutor_panel.py`（课堂界面）。

## 1. 产品判断

一道竞赛几何题不是一张图，也不是一段话，而是**一个构造 + 一串关于它的事实**。
geobench 已经有两半：DSL 负责构造，判定器负责事实。所以讲题功能不应该另起一套，
而应该把这两半交给模型去**使用**：

- 模型读题、画图、拆步骤、写讲解；
- 解析器判断图能不能画；
- 本地精确内核判断每一步的几何事实；
- 模型根据内核的结果和学生的问题继续讲。

一句话：**模型负责提方案，内核负责说“这条是真的”**。这和 Lean/Coq + LLM 的分工
是一样的，也是这个产品相对“聊天式解题”的护城河。

## 2. 市面上的对照

下面是按公开产品/论文的已知形态做的对照，不是实时抓取的数据。

| 类型 | 代表 | 它强在哪 | 它缺什么 |
|---|---|---|---|
| 动态几何 | GeoGebra、Desmos、网络画板 | 拖动、构造、课堂演示成熟；GeoGebra 还能用 `Prove` 做符号证明 | 没有“讲题”的对话层；证明结果不进入教学步骤 |
| 自动证明器 | JGEX、Geometry Expert、AlphaGeometry / AlphaGeometry 2、FormalGeo | 能给出形式证明或搜索证明；AlphaGeometry 在奥赛题上很强 | 面向研究/评测，不是课堂界面；证明语言对老师不友好 |
| AI 学习助手 | Khanmigo、Photomath、Gauth、小猿搜题、作业帮、学而思九章、豆包爱学 | 讲人话、会追问、能识别题目；Khanmigo 的苏格拉底式提示很成熟 | 多数是“静态题图 + 文字步骤”；图不能动，步骤不能逐条机器核对 |
| 互动课程 | Brilliant、Mathigon | 交互设计好，学习路径清晰 | 内容是预先编排的；不会针对学生自己贴的题现做一课 |
| 技术同类 | Lean + LLM（LeanDojo、COPRA）、MCP/工具调用 Agent、Jupyter AI | “模型提议、工具验证”的闭环；状态化工具调用 | 没有面向中学几何的 DSL、图形和课堂语言 |

**空白点**：把“动态几何 + 精确判定 + 会动图的 AI 教练”放在同一个产品里。
大多数产品要么只有图，要么只有文字；要么只会答题，要么只会证明。geobench 的
差异是：**AI 说的每一步都能在图上指出来，并且能被内核核对**。

## 3. v1 的运行方式

```
题目文字
  │
  ▼
build_lesson ──► JSON：figure + goal + steps
  │                 │
  │                 ├─ parse_dsl：图能不能画
  │                 ├─ check_figure：有没有无值对象
  │                 └─ 每条 claim：内核关系目录 + 对象类型校验
  ▼
画布：加载 figure（辅助对象已隐藏）
  │
  ▼
一步：reveal（显示辅助对象） + highlight（高亮） + say（讲解） + claim（内核核对）
  │
  ▼
学生提问 ──► answer_question ──► 回复 JSON：say + highlight/reveal/construct/claim
  │
  ▼
画布：应用动作；claim 交给内核；结果写回对话
```

### 课程 JSON

```json
{
  "title": "等腰三角形三线合一",
  "figure": "点 A(0,4) B(-3,0) C(3,0)\nAB = 线段(A,B)\n...\nD = 中点(B,C)\n隐藏 D\n...",
  "goal": "证明 AD ⊥ BC",
  "steps": [
    {
      "say": "D 是 BC 的中点，先看 AD 把三角形分成两半。",
      "reveal": ["D"],
      "highlight": ["A", "B", "C", "D"],
      "claim": {"kind": "equal_length", "args": ["A", "B", "A", "C"], "scope": "identity"},
      "ask": "这两个三角形有哪些边相等？"
    }
  ]
}
```

### 学生追问 JSON

```json
{
  "say": "把 AD 连起来：它既是中线，也是高。",
  "highlight": ["A", "D"],
  "reveal": ["D"],
  "construct": [{"op": "line.free", "args": ["A", "D"], "id": "AD"}],
  "claim": {"kind": "perpendicular", "args": ["AD", "BC"], "scope": "identity"},
  "ask": "你能看出哪个角是直角吗？"
}
```

### 把条件画进图里

这是 v1 最容易踩的坑：题目说 `AB = AC`，如果只是把三个点**摆成**等腰，内核在
“对任意图形成立”的作用域下会正确地找到反例。条件必须变成构造：

- `AB = AC` → `w = 圆(A,B)`，`C = 圆上的点(w, 1/3)`；
- `D 是 BC 的中点` → `D = 中点(B,C)`；
- `P 在 l 上` → `P = 线上的点(l, …)`；
- 直角/平行 → `垂直` / `平行`；共圆 → `外接圆` + `圆上的点`；
- 直线与圆**已知一个交点**，另一个交点必须写 `交点(直线, 圆, 另一交点)`。
  `0/1` 是线的分支号，不保证是“另一个”；用错会选到已知点（垂心题里就是 A）。

这一条已经做成**交点 lint**：新课里如果某个新交点与直线/圆的定义点重合，
会在核对 claim 之前直接提示“你选到了 A，请用另一交点”，而不是丢一页代数。

课程里每一步的 `claim` 强制用 `scope=identity`；模型如果选择 `instance` 来
“躲开”反例，会被拒绝并收到“把条件画成构造”的反馈。

### 校验边界

- `figure` 必须能过 `parse_dsl`，并且没有无值对象；失败会把解析器的原话回给模型重试。
- `reveal` / `highlight` 只能引用图里已有的对象。
- `construct` 只能用已实现的算子，id 不能重名；画不出来会在对话里明确说“没画出来”。
- `claim` 必须是内核认识的关系，参数个数和类型都要对；内核说“不成立”就显示“不成立”，
  不会因为模型说“成立”而改口。
- 模型不写“成立/不成立”；它只写“要核对什么”。

## 4. 教学原则（写进 prompt 的硬规则）

1. **先图后话**：每一步先告诉学生看哪个对象，再解释为什么。
2. **一步一个想法**：3–8 步；不把完整证明一次倒出来。
3. **用图上的名字**：说 `M`、`AD`，不说“这条线”。
4. **先问再讲**：每步尽量留一个小问题；学生答错时退回更小的一步。
5. **不编定理**：引用定理时写条件和结论；不用“显然”“易证”。
   **`angle_equal` 比的是无向角**：同弦两侧的圆周角可能互补，所以只在某些摆放下相等
   的角不要写成 `claim`；把角度链写在 `say` 里，用有向角讲清楚。
6. **claim 宁少勿错**：不确定对所有摆都成立的，省略 claim；这比一条假 claim 好。
7. **承认不会**：条件不足、需要分类讨论、超出图形时直接说明，不补条件。
8. **辅助线要克制**：能不加就不加；要加就说明“为什么要加”。

## 5. v1 不做什么

- 不做图片 OCR：题目先以文字贴入；拍照识题是下一步。
- 不声称“整份证明形式化验证”：内核核对的是**每条几何事实**，不是整段推理的逻辑链。
  讲解里的定理引用、分类讨论仍由模型负责，老师要能看懂、能质疑。
- 不自动批改整份学生解答：学生可以用右侧“一句话判定”核对某一条断言，但还没有
  “按步骤批改一份手写证明”的界面。
- 不把模型当裁判：没有模型也能画图、拖动、用手动判定；讲题是增强，不是依赖。

## 6. 路线图

| 阶段 | 内容 |
|---|---|
| v1（本次） | 文字题目 → 图 + 3–8 步课程；逐步 reveal/highlight/claim；学生追问；辅助线 construct |
| v2 | 学生先试一步：输入自己的断言，内核核对后教练再点评；“上一步/回到某步”；补**有向角/补角**判定，让同弦圆周角这类角度链也能被内核核对，而不是只能省略 claim |
| v3 | 拍照/截图识题（OCR + 图形理解），仍是“模型提议、解析器/内核校验” |
| v4 | 定理库：把常用定理做成可引用的 lemma，讲解可以注明“用了哪个定理的哪个条件” |
| v5 | 课堂模式：一份课程分发给学生、进度同步、错步统计 |

## 7. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 模型画错图 | 解析器 + 内核拒绝，带原因重试；不把坏图放上画布 |
| 模型讲错一条事实 | 每条 claim 内核核对；不成立就红字显示，不静默通过 |
| 模型“证明”逻辑跳跃 | prompt 要求写条件和结论；v1 明确“内核只核对事实”；v2 再引入学生步骤批改 |
| 模型服务不可用 | 讲题是可选增强；作图、拖动、手动判定、导出都不依赖模型 |
| 长回复/成本 | 课程 3–8 步、回复短；provider 的 token 上限单独设置 |
| 课堂隐私 | 只有点“生成课程/问”时才发送题目和图形；界面明确写出 |
